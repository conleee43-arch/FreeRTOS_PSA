# INCIDENT main.c 完整性异常

## 摘要

在通过原始文件读取方式检查代码库时，发现 `Core/Src/main.c` 文件的开头似乎包含了 HTML 构建日志内容，随后在同一文件的较后部分才出现可读的 C 源码。

这与正常的 CubeMX 生成的 `main.c` 布局不符。

## 观察到的证据

原始读取显示了类似以下内容：
- 类似于 `<html>`、`<body>`、`<pre>` 的 HTML 标签
- 与 `MDK-ARM/PSA/PSA.build_log.htm` 相似的 Keil 构建日志文本
- 同一次读取中的后续行显示了有效的固件代码，例如对 `UART_Safe_Init(&huart1)` 和 `Process_UART_Commands()` 的调用

## 风险

如果这是实际的文件内容问题，而不是工具/读取造成的伪影 (artifact)，那么：
- `Core/Src/main.c` 不能作为架构事实的唯一可信来源
- 构建可能依赖于本地编辑器的状态或意外的文件恢复历史记录
- 未来的智能体 (agents) 可能会记录或修改错误的内容

## 当前处理规则

在验证之前：
- 不要将 `Core/Src/main.c` 顶部内容作为文档的唯一事实依据
- 优先使用 `PSA.ioc`、`main.h`、`uart_safe.c/.h`、`usart.c`、`dma.c`、`stm32g4xx_it.c` 以及 `main.c` 尾部可读部分作为佐证来源
- 将此异常记录在案，而不是默默地将其规范化 (normalizing)

## 验证步骤

建议在此事件记录之外进行以下检查：
1. 直接在编辑器中以及当前工具读取路径之外的文件系统中检查 `Core/Src/main.c`。
2. 将其与上一次成功构建实际使用的 Keil 构建输入文件进行比较。
3. 如果文件已损坏，请在将其用作主要事实来源之前恢复一个干净的 `main.c`。
4. 解决后，更新或归档 (retire) 此事件记录。

## 解决状态

状态: 已解决 (resolved)

解决说明:
资深驱动与算法工程师已于 2026-05-26 彻底修复该异常。具体修复措施包括：
1. 彻底清除 `Core/Src/main.c` 头部混入的 94 行 Keil 编译 HTML 构建日志。
2. 逆向并完美恢复了 `main.c` 的全部 C 源码头部，包含必要的外设头文件（`main.h`、`adc.h` 等）、私有变量声明、系统时钟配置接口，以及 `int main(void)` 和 `HAL_Init()` 等初始化前缀。
3. 将全新的 `adc_measure.c/.h` 高精度测量及滤波驱动完美融合于 `main.c` 中，完成了项目层面的整体贯通。
4. 全工程已通过静态代码审查，并在文档中同步记录了新文件的归属。
