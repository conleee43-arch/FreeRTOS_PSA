# ARCH_gui-console — 上位机 GUI 控制台架构与运行行为规范

---

## 1. 核心设计目的

`gui/main.py` 承担本项目 PySide6 上位机控制台的唯一应用入口职责。它的设计目标不是复刻下位机业务状态机，而是作为一个轻量、确定、可观测的串口交互壳层，完成以下三项工作：

1. 建立和维护 PC 到 STM32 固件的串口连接。
2. 将下位机输出的文本行协议安全搬运到 UI 主线程。
3. 依据已定义的协议语义刷新监测控件、诊断控件和终端日志。

本文件只定义 GUI 自身的架构边界、线程职责、UI 状态语义和运行期契约。任何具体的文本协议格式、命令字面量、正则表达式和字段顺序，唯一真理源均位于 [STANDARDS_interface.md](STANDARDS_interface.md#standards-interface)。

## 2. 组件边界

### 2.1 `SerialReaderThread`

`SerialReaderThread` 是 GUI 的后台串口读取线程，职责仅限于：

- 轮询 `serial.Serial` 的输入缓冲。
- 将读到的原始字节通过 `raw_data_received` 发回 UI 线程。
- 以 `\n` 为物理行结束符切分缓冲区。
- 以 `utf-8` 容错解码单行文本，再通过 `line_received` 发回 UI 线程。
- 当串口断开或运行异常时，通过 `error_occurred` 通知 UI 线程。

它绝不直接操作任何 Qt 可视控件，也不拥有协议业务语义。

### 2.2 `PSAFirmwareConsole`

`PSAFirmwareConsole` 是唯一的主窗口与状态汇聚点，职责包括：

- 创建并布局所有监测、诊断、系统控制与终端控件。
- 管理串口对象、读取线程和端口扫描定时器。
- 将 `Measure`、`Calc`、`State` 三类协议行映射到 UI 显示。
- 负责连接态、断开态、异常态和复位后的控件状态收口。

它可以消费协议语义，但不拥有协议格式定义本身。

## 3. 运行时数据流

GUI 运行时遵循以下单向流：

1. 用户在主窗口中选择串口和波特率。
2. `open_serial()` 创建 `serial.Serial`，随后启动 `SerialReaderThread`。
3. 读取线程持续收集字节流，并以“原始字节事件”和“完整文本行事件”两条支路回送主线程。
4. `handle_raw_data()` 仅在 Hex 显示模式下追加原始报文。
5. `handle_line_received()` 根据协议类别分别刷新 ADC 测量值、内阻诊断值和状态标签。
6. 若线程报告异常，`handle_serial_error()` 统一收口到 `close_serial()`，避免线程悬挂和 UI 假在线。

该链路必须保持“后台读取、主线程渲染”的单向约束，禁止在读取线程内直接触碰可视控件。

## 4. UI 状态模型

### 4.1 连接状态

GUI 至少存在以下四种运行状态：

- **未连接**：端口与波特率控件可编辑，发送、断开、系统复位按钮禁用。
- **已连接**：端口与波特率控件锁定，发送、断开、系统复位按钮启用。
- **异常断开**：由后台线程错误统一触发 `close_serial()`，避免残留线程和失效串口句柄。
- **复位清空**：发送 `SystemReset` 后，立即清空关键诊断显示（如内阻、锁存值、IOC），避免 MCU 重启期间旧诊断结果误导操作者。

`ui_state_connected()` 是连接态控件启禁的统一收口点。新增控件若受连接状态影响，必须在该函数中统一处理。对于由协议状态驱动的派生 UI（例如 2A 挂起按钮），其样式和文案仍由专属状态更新函数维护，但断连路径必须显式调用这些状态更新函数以清理残留显示。

### 4.2 端口扫描

端口扫描由 `QTimer` 周期性触发，仅在当前未建立串口连接时更新端口列表。其目的在于：

- 避免用户在离线时手动刷新。
- 避免在连接已建立时热刷新下拉框，导致串口选择与实际会话对象脱节。

## 5. 协议视图与虚拟状态

GUI 消费的是“协议视图”，而不是固件内部 C 枚举的裸暴露。因此允许存在面向交互体验的虚拟状态映射。

`WAIT_2A_PAUSED` 就属于此类虚拟状态：它用于表达“当前仍处于 `WAIT_2A_STABLE` 阶段，但计时已被人工挂起”的 GUI 可视语义。该状态可驱动：

- 诊断标签文案切换。
- 挂起/恢复按钮文案与样式切换。
- 是否允许继续发送恢复命令。

虚拟状态只能出现在 GUI 视图层与接口标准层，不应反向要求固件核心状态机枚举强行膨胀。

## 6. 兼容性与测试契约

### 6.1 兼容性保留项

GUI 中允许存在少量“为保持测试契约和布局兼容而保留”的结构。例如隐藏的 `system_group` 仍需保留在布局树中，以满足既有自动化校验对控件层级的断言。

若未来准备删除、重命名或移动此类结构，必须先更新对应测试，再调整实现。

### 6.2 自动化校验

GUI 架构和运行行为的回归由以下脚本共同守护：

- [../tests/check_gui_runtime_behavior.ps1](../tests/check_gui_runtime_behavior.ps1)：验证控件布局、状态文本、2A 挂起/恢复按钮行为等 GUI runtime 契约。
- [../tests/check_uart_gui_protocol.ps1](../tests/check_uart_gui_protocol.ps1)：作为上层回归入口，串联 GUI runtime 校验、状态机行为校验以及协议一致性检查。

新增 GUI 交互行为时，若会影响控件命名、默认启禁状态、协议状态映射或日志收口流程，必须先扩展测试再修改实现。

## 7. 禁止事项

本文件对应的 GUI 架构层禁止包含以下设计漂移：

- 在 GUI 文档中复制协议正则、命令字面量或字段顺序。
- 在后台线程中直接操作 Qt 控件。
- 让多个槽函数分别维护同一连接态启禁规则。
- 为单一临时需求引入独立协议编解码框架或过度抽象。

GUI 架构演进必须优先保持当前“小入口、单线程渲染、后台搬运”的稳定模型。
